# Library/domain specification

Adapt this template to the repository's conventions. Replace the guidance below with the actual contract; omit irrelevant sections.

## Scope

Describe the purpose, public API, and explicit exclusions. Identify the contract version and dependencies/platforms that affect behavior.

## Representations and shared rules

Define accepted values, defaults, null/missing/empty distinctions, Unicode units, numeric rules, ordering, mutation, and error detection as relevant. Define required environmental inputs and permitted language variation.

## Function or operation

Give a language-neutral signature and summary. Name its observable rules, boundaries, failure cases, and examples. Use stable rule identifiers if the repository supports them.

## Fixture conventions

Describe case containers, argument mapping, comparisons, error cases, named helpers/scenarios, invariants, and metadata. Reuse established shared conventions by reference instead of duplicating them.

## Compatibility

Record changed behavior and how existing callers/implementations migrate. Keep unresolved behavior clearly marked as a draft decision.
